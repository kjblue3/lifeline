# LifeLine Frontend

Intelligence Without Interruption.

LifeLine uses plain HTML/CSS/JavaScript served by FastAPI. Hackathon inference
is **local-only on the Dell**, not cloud AI. No backend or model files are
changed by this frontend integration. There are no external assets or CDNs.

## Run On The Dell

From the project folder with Windows ARM64 Python 3.11 installed:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Open http://127.0.0.1:8000/. Install dependencies before disconnecting. Do not
transfer CoShell's Linux `.venv` to the Dell. Actual ARM64 model/runtime testing
must happen on the Dell. Mobile layout support does not mean a phone runs the
model; the backend and model run on the Dell.

## Connected API

`web/api.js` centralizes same-origin API calls. Existing request formats are
confirmed from `chat.py`; no new endpoint names or request fields are required.

```text
GET /api/status
{ok:true,data:{mode,local:{configured,ready,model,message},
              references:{installed,count},offline_ready,...}}

POST /api/ask
Request: {question:"..."}
Response: {ok:true,data:{id,answer,mode:"local",simulated:false,sources,notice}}
Error: HTTP 503, {ok:false,error:{code,message}}
```

Only the current question is sent. The profile and visible conversation history
are never uploaded. Follow-ups are currently independent questions: visible
history is not backend conversation memory. Refreshing clears frontend data.

Real answer rendering requires `mode: "local"` and rejects `simulated: true`.
Optional `sections:[{title,content}]` render as plain text. Sources show actual
returned titles/names and HTTP(S) links; unsafe URLs are not linked. No sample
medical answers or citations are generated by frontend code.

## Local AI Status

`LifeLineStatus` polls approximately every four seconds after each completed
request, including while the user types or an ask is pending. Slow requests do
not overlap, and manual refresh shares any pending request. Polling changes
neither conversation nor draft/focus.

- `local.ready: false`: **Local AI Not Ready**, with the backend's `local.message` beneath the input.
- `local.ready: true`: **Local AI Active**. The model name appears in connection details.
- Failed or invalid status: **Unable to Check AI Status**, clearing stale readiness and library claims.
- `references.installed`: displays actual availability and returned reference-topic count.
- `offline_ready`: separately controls complete-system readiness in connection details. AI readiness alone is not full offline readiness.

When the backend is reachable, submitting a question is allowed even if the
model is not ready, so its actual 503 error can be shown. A failed ask preserves
the visible user question and draft, displays the actual error when provided,
and offers manual Retry. It never creates an assistant answer or automatically
retries inference. If status becomes unreachable, sending pauses until recovery.

## Internet Connectivity

Internet connectivity and local AI readiness are independent.
`LifeLineConnectivity` currently reports **Internet Connection Unknown** because
the backend has no confirmed external-connectivity field. It makes no external
probes and does not treat `navigator.onLine`, backend reachability, `mode`, or
`offline_ready` as evidence of internet availability.

The background currently remains neutral `#F3F4F6` in real operation. Styling
supports confirmed `available` (`#F0F9F1`) and `unavailable` (`#FFF1F0`) states
through `body[data-connectivity]`, with a 0.5-second transition. Reduced-motion
preferences disable it. Once Aryan supplies a confirmed connectivity contract,
wire that result into the independent connectivity service and indicator.
Do not enable green/red using AI status. No cloud integration remains.

The former `?preview=1` AI simulator was removed. That query no longer enables
simulated statuses or answers. Automated tests use explicit intercepted fixtures
instead of pretending a working model exists in the application.

## Other Screens

Chat, Prepare Trip, and Medical Profile retain their existing navigation,
collapsible desktop sidebar, accessible mobile layout, and large controls.
Emergency Help remains accessible regardless of AI readiness. The US `tel:911`
link needs a compatible dialer and supported communication service; LifeLine
does not contact responders automatically.

Trip environment and description inputs are interactive, with planning-topic
suggestions clearly distinguished from downloaded references. The prepare
button remains disabled and says **Trip preparation is not connected yet**.
Future trip preparation must supplement rather than replace the general library.
Medical-search/trip capabilities in `api.js` remain disabled until their API and
storage-confirmation contracts are agreed with Aryan.

The six-field medical profile is optional and explicitly fictional. Save, edit,
and remove work in page memory only. No localStorage, profile endpoint, or
profile-to-AI transmission is used. Secure persistence is future backend work.

## Test The Current 503 Backend

1. Start the server and open the homepage. Expect Local AI Not Ready and the actual backend message.
2. Enter a fictional question and send it. Expect the actual HTTP 503 error and a Retry button, not a medical answer.
3. Confirm the question remains visible and in the input. Wait: no inference is retried automatically.
4. Retry manually. Open Emergency Help; it remains available regardless of model status.

## Test After ExecuTorch Is Connected

1. Start Kiran's tested local adapter and the backend on the Dell.
2. Without reloading, confirm polling changes the label to Local AI Active and shows the model name in connection details.
3. Ask a fictional question; verify real local output and only backend-returned source links.
4. Check library availability/count separately. Do not claim complete readiness until `offline_ready` is true.
5. Disconnect Wi-Fi and ask another fictional question. Messages must remain and actual local inference must still work. Internet remains unknown until a reliable connectivity contract exists.
6. Stop the backend; within a failed poll, expect Unable to Check AI Status rather than stale readiness. Restart it and confirm automatic recovery.
